How plausible deniability works

The vault file contains two independently encrypted slots. Each slot is a standard AES-256-GCM ciphertext with its own randomly generated salt and IV — cryptographically indistinguishable from any other AES-GCM ciphertext. The slot order is randomised at creation time (50/50), so even knowing the vault format reveals nothing about which slot holds the real data. Both slots are padded to the same size (the larger of the two messages), so the file size reveals nothing about which message is longer. An adversary with the vault file and one password can decrypt one slot and get a valid message — but cannot prove another slot exists, because every fixed-length random-looking binary blob is consistent with a valid AES-GCM ciphertext. The vault format: [magic 4B][slot0_salt 16B][slot0_iv 12B][slot0_ct N B][slot1_salt 16B][slot1_iv 12B][slot1_ct N B].
