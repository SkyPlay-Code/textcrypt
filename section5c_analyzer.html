How the analysis works

Entropy is estimated as log₂(poolSize) × length, where poolSize is derived from the character categories present (lowercase 26, uppercase 26, digits 10, symbols ~32). This is a conservative theoretical estimate — patterns in the password (keyboard walks, repeated characters, common words) reduce real-world entropy significantly. Crack times assume an attacker is performing an exhaustive brute-force search at the given rate, testing the average half of all combinations. Pattern detection checks for sequential keyboard rows (qwerty/dvorak), sequential digits (1234), repeated characters (aaaa), leet-speak substitutions, and common dictionary words to flag easily guessable passwords even if they appear long.
